<Title>Accordion</Title>

<Subtitle>
  A vertical stack of expandable sections, registered as the
  <code>garnet-accordion</code> custom element. In Storybook it is grouped under
  <strong>Action Components → Accordion</strong>. Content is driven by a
  <code>data</code> array; each row becomes an <code>AccordionItem</code>
  (<code>garnet-accordionitem</code>) with a button header and a sliding panel.
  Optional <code>defaultOpen</code> sets the initial open state for every item.
</Subtitle>

## Overview

`Accordion` imports `accordiondata.json` as the default for <code>data</code>,
then renders one <code>AccordionItem</code> per entry. Each item receives
<code>title</code> and <code>entry</code> (plain text) and wraps the same text
in a default <strong>slot</strong> (for example a <code>&lt;p&gt;</code> in the
current implementation). <code>AccordionItem</code> shows slot content when the parent provides children,
and otherwise falls back to the <code>entry</code> string inside the panel.

<code>defaultOpen</code> is forwarded to each item as <code>isOpen</code>, so
when <code>true</code> every section starts expanded; users can still collapse
them with the toggle button.

Panel open/close uses <code>slide</code> from <code>svelte/transition</code> on
the list wrapper. Styles live in each component’s <code>&lt;style&gt;</code>
block.

## Usage in Svelte

```svelte
<script lang="ts">
  import Accordion, { type AccordionData } from '$lib/components/Accordion/Accordion.svelte';

  const data: AccordionData[] = [
    { title: 'Question', text: 'Answer copy goes here.' },
  ];
</script>

<Accordion {data} />

<Accordion {data} defaultOpen />
```

## Usage as a custom element

<code>garnet-accordion</code> and nested <code>garnet-accordionitem</code> come
from the respective <code>customElement</code> options. Feeding complex
<code>data</code> from raw HTML is usually impractical; prefer Svelte or
setting properties in JavaScript after the elements are defined. You can set
<code>defaultOpen</code> the same way when your custom-element build exposes it
as a property.

## Accessibility

- Each header is a <code>&lt;button&gt;</code> with <code>aria-expanded</code>
  reflecting open state.
- For stronger region semantics you can later wire
  <code>id</code>/<code>aria-controls</code> between the button and the
  expanded panel.
