## Overview

`Table` composes `Grid.svelte` and `Cell.svelte`. It renders an `<h1>` with `label`, then passes
`columnCount` and `rowCount` to `Grid` as `columns` and `rows`, along with `border`. It iterates
`itemCount` times and mounts one `Cell` per iteration, forwarding `displayImages`, `imageLabel`, and
`displayImageLabels`.

`Grid` uses CSS `display: grid` with `grid-auto-flow: column`, so items fill column-first across
`columns` tracks and `rows` row tracks. The grid container also has a default `1px solid #000000` border
in its scoped styles; the inline `border` style from props overrides the outer edge when set.

When `displayImages` is `false`, each `Cell` exposes a default slot (unused by `Table` today, so cells
appear as empty bordered regions). When `displayImages` is `true`, each cell shows `noimage.jpg` with
`alt="placeholder"` and `data-testid="placeholderImage"`. With `displayImageLabels` true, a dark
overlay at the bottom of the image shows `imageLabel`.

## Usage in Svelte

```svelte
<script lang="ts">
  import Table from '$lib/components/Table/Table.svelte';
</script>

<Table
  label="Photo gallery"
  columnCount={3}
  rowCount={2}
  itemCount={6}
  displayImages
  displayImageLabels
  imageLabel="Untitled"
/>

<Table
  label="Layout sketch"
  columnCount={2}
  rowCount={2}
  itemCount={4}
  border="2px dashed #265573"
/>
```

## Usage as a custom element

`<garnet-table>` comes from `customElement="garnet-table"`. Set numeric and boolean props as element
properties from JavaScript or Svelte for reliable updates. Child primitives are also available as
`<garnet-grid>` and `<garnet-cell>` if you compose layouts manually; `Table` wires them together with
the props above.

## Accessibility

- The section title uses a native `<h1>`; use a single logical heading level per page when embedding
  this component.
- Placeholder images use a fixed `alt="placeholder"`; for real content, prefer composing `Cell` with
  meaningful `alt` text or slot content instead of the demo image mode.
- The grid is a visual layout only; it is not a semantic HTML `<table>`. For tabular data with row and
  column headers, use `<table>` markup or add appropriate ARIA roles if you need screen-reader table
  navigation.
